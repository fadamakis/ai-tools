# Security reports

Use the repository's **Security → Report a vulnerability** [private reporting form](https://github.com/fadamakis/ai-tools/security/advisories/new) when it is enabled. It must be enabled and checked during the public launch before announcement. Do not post credentials, private source, personal task data, or exploit details in a public issue.

If that button is unavailable, use the maintainer's existing private contact channel to request a secure reporting destination without including the sensitive material. No email address or response-time commitment is implied by this document.

Include affected product and version, a minimal reproduction, impact, and a suggested mitigation where available. Redact secrets and personal data. Report the smallest relevant excerpt rather than a full database or review archive.

Maintainers support the current release channel and publish compatible fixes under newer versions. Older vulnerable versions are not made safe by changing repository visibility. Revoke exposed credentials before repository cleanup, and coordinate any necessary history remediation privately.
